why this exists

LLMs hallucinate facts and hallucinate the checks on those facts. Ask an LLM to verify its own claim and it runs the same error-prone process again — the check is circular. "Double-checking" with an LLM is like asking the same witness to corroborate their own testimony.

Proof Engine breaks the circle by routing every claim through a gate the LLM can't fake. Numbers are computed by Python — Python doesn't hallucinate. Quotes are fetched from live URLs and matched against the actual page text — a fabricated citation fails the match, and a partial match downgrades the verdict so the gap is visible. Constants come from reviewed, version-controlled code — not from the LLM's memory.

The design principle: when the LLM hallucinates, the error breaks visibly rather than hiding.

The LLM is useful: it finds sources, writes code, formalizes claims. But it is never trusted to be the verification. It is an untrusted author whose every claim must pass through a deterministic checkpoint. When it hallucinates, the pipeline breaks visibly instead of hiding the error.

what it can and can't do

works well for

  • Factual claims with verifiable evidence — dates, numbers, quotes, statistics from citable sources
  • Mathematical assertions — anything Python and sympy can compute deterministically
  • Debunking or confirming specific claims — "Did X really say Y?" or "Is statistic Z accurate?"
  • Compound claims — decomposes "X and Y" into independently verified sub-claims

doesn't work for

  • Causal claims — "X caused Y" gets PARTIALLY VERIFIED at best; the engine verifies facts but can't weigh competing causal theories
  • Broad literature synthesis — "coffee reduces diabetes risk" requires a systematic review, not a proof
  • JavaScript-rendered pages — citation verification degrades when the source requires a browser to render
  • Absence-of-evidence — search-based facts reach SUPPORTED at best, never PROVED; the engine can't prove something doesn't exist
  • Contested definitions — "Is a hot dog a sandwich?" depends on the definition, not evidence
  • Deep original mathematics — the engine isn't a theorem prover; it handles computations, not novel conjectures

how is this different?

"Why not just ask ChatGPT to check?" Because the check uses the same mechanism that produced the error. If the LLM hallucinated a fact, asking it to verify the fact just hallucination-checks the hallucination. Proof Engine moves verification out of the LLM entirely — into Python code and live page fetches that either pass or fail mechanically.

"Why not use Perplexity / search-grounded AI?" Search-grounded tools find relevant pages but still let the LLM summarize and interpret what's on those pages. Proof Engine goes further: it fetches the URL, matches the quoted text against the live page (after normalizing Unicode and HTML), and extracts values from the matched text programmatically. If the match is only partial, the verdict downgrades to flag it. The difference is between "the LLM read a source and told you what it said" and "here's the code that fetched the source, checked the text, and reported what matched — run it yourself."

"Why not just link to sources like Wikipedia?" A link says "the evidence is over there." A proof says "here's the evidence, here's the code that checked it, and here's what happened when it ran." Every proof is a re-runnable Python script. You don't have to trust the summary — you can execute it.
